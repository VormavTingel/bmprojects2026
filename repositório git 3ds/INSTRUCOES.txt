EXERCÍCIO COLABORATIVO - HTML5, CSS, JAVASCRIPT E GIT
=====================================================

OBJETIVO
Em grupos, completar as lacunas [PREENCHER] do catálogo de cards sobre HTML5,
CSS moderno e JavaScript. O catálogo foi montado para abranger praticamente
todos os elementos HTML atuais e uma cobertura ampla dos principais recursos de
CSS e JavaScript usados em layouts, funções, responsividade e interfaces atuais.
Cada grupo deve pesquisar o item indicado, escrever uma descrição correta com as
próprias palavras, testar a página no navegador e enviar a alteração pelo fluxo
correto de branches e Pull Requests (PRs).

COMO A PÁGINA FUNCIONA
1. O aluno abre o arquivo index.html no navegador.
2. O index.html carrega automaticamente style.css e script.js.
3. O arquivo style.css cuida da aparência, do layout dos cards e da
   responsividade da página.
4. O arquivo script.js guarda a lista chamada "conteúdos", com muitos cards de
   HTML, CSS e JavaScript.
5. Quando a página abre, o script.js lê essa lista e renderiza cada item como
   um card visível no index.html.
6. O aluno localiza no script.js a lacuna atribuida ao seu grupo, substitui
   [PREENCHER] pela descrição correta e salva o arquivo.
7. Ao atualizar o index.html no navegador (F5), a nova descrição aparece no
   card correspondente.
8. Depois de conferir o resultado, o grupo envia a alteração por sua branch e
   abre um Pull Request para a branch main.

ORGANIZAÇÃO DA TURMA (31 ALUNOS)
A conta 31 dividido por 4 deixa 3 alunos. Para que exista uma dupla, a
composição precisa ter excepcionalmente um grupo com 5 pessoas:

- Grupos 1 a 6: 4 alunos em cada grupo (24 alunos);
- Grupo 7: 5 alunos;
- Grupo 8: 2 alunos.
- Total: 24 + 5 + 2 = 31 alunos.

DIVISÃO DAS LACUNAS
O catálogo possui muitas lacunas [PREENCHER], distribuidas de forma aleatória
entre HTML, CSS e JavaScript. Apróximadamente 45% dos cards ficaram como
exercício.

Sugestão de divisão:
- Cada grupo fica responsável por cerca de 19 lacunas;
- O grupo 7, por ter 5 integrantes, pode ficar com cerca de 20 lacunas;
- A dupla pode ficar com menos lacunas ou com lacunas mais simples, a critério
  do professor;
- Cada grupo deve pegar lacunas misturadas entre HTML, CSS e JavaScript.

Cada grupo deverá substituir somente o texto [PREENCHER] dos cards que recebeu
por descrições claras. Cada descrição deve explicar para que o recurso serve e
citar um exemplo curto de uso. Não apague nem altere o trabalho atribuído a
outro grupo.

FLUXO DE TRABALHO COM GIT E GITHUB
1. Antes de começar, atualize a branch principal:
   git switch main
   git pull origin main

2. Crie sua própria branch. Troque 01 pelo número do grupo e ajuste o nome do
   item pesquisado:
   git switch -c grupo-01/card-header

3. Edite os arquivos, confira a página no navegador e verifique as alterações:
   git status
   git diff

4. Registre o trabalho com uma mensagem clara:
   git add "repositório git 3ds"
   git commit -m "Completa card header - grupo 01"

5. Publique a branch no repositório remoto:
   git push -u origin grupo-01/card-header

6. No GitHub, abra um Pull Request da branch do grupo para a branch main.
   Escreva no PR: integrantes, card pesquisado, resumo e como o teste foi feito.

7. Outro grupo deverá revisar o PR. Só faça o merge após a aprovação e após
   resolver possíveis conflitos. Não envie o trabalho diretamente para main.

8. Após o merge, sincronize novamente seu computador:
   git switch main
   git pull origin main

CRITÉRIOS DE ENTREGA
- Descrição correta, clara e escrita com as próprias palavras;
- Exemplo curto de uso dentro da descrição;
- Página funcionando sem erros no console do navegador;
- Card aparecendo corretamente ao abrir ou atualizar o index.html;
- Alteração restrita aos arquivos necessários;
- Branch e commits com nomes claros;
- Pull Request preenchido e revisado por outro grupo;
- Participação registrada de todos os integrantes.

OBSERVAÇÃO
No GitHub, a solicitação é chamada de Pull Request. Em plataformas como GitLab,
o mesmo processo é normalmente chamado de Merge Request.
